# PIT / pitest (Java, Kotlin)

Check the plugin version and existing configuration in the build file before running anything.

## Detecting it

- Maven: `org.pitest:pitest-maven` in `pom.xml`.
- Gradle: the `info.solidsoft.pitest` plugin in `build.gradle` or `build.gradle.kts`.

Do not add the plugin if it is missing.

## Running on the scope

PIT works at class granularity. In diff modes, target the classes that contain the changed hunks and ignore survivors outside those lines.

```bash
# Maven
mvn test-compile org.pitest:pitest-maven:mutationCoverage -DtargetClasses=com.acme.pricing.Discount

# Gradle (the plugin exposes targetClasses in the pitest { } block; some versions accept it as a project property)
./gradlew pitest
```

`-DwithHistory` (Maven) reuses previous results. Changed-lines-only analysis (`+GIT`) is part of the commercial Arcmutate extensions; don't assume it is available.

## Reading results

Reports go to `target/pit-reports/` (Maven) or `build/reports/pitest/` (Gradle). Enable `XML` in `outputFormats` for a machine-readable `mutations.xml` when the project already allows it; otherwise read the console summary and the HTML.

Statuses: `KILLED`, `SURVIVED`, `NO_COVERAGE`, `TIMED_OUT` (counts as detected), `MEMORY_ERROR`, `RUN_ERROR`.

## Kotlin

Without Arcmutate's commercial Kotlin plugin, PIT mutates compiler-generated bytecode. Before classifying survivors, discard any that point to generated members (see [kotlin.md](kotlin.md)).
